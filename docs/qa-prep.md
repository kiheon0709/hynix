제출 직후 바로 나온다. **질문은 내 제출물(파일명·문서 내용)을 보고 맞춤으로 나온다.**
각 답은 **결론 1줄 → 이유 2줄 → 근거(파일·함수·테스트명·명령) 1줄**. 5분이면 5~7문장. 막히면 결론 한 줄이라도 쓰고 넘어간다(. 만 찍고 나가지 않는다).

## 유형별 답 골격 (빈칸만 머리에 넣고 들어간다)
**흐름**
> `____.py`(입력 읽기·검증) → `____.py`(핵심 규칙: ____ ) → `____.py`(출력/화면). 원본 데이터는 ____가, 계산 결과는 ____가 갖고 다른 모듈은 읽기만 한다. 이렇게 나눈 이유는 ____ 를 따로 테스트하려고.

**검증 구분**
> 자동검증: `test_____`, `test_____` (`python3 -m unittest -v`로 확인, N개 통과). 가정: ____ 는 담당자 답변 "____"에 기댐, 틀리면 `____` 함수만 바뀜. 미구현·미검증: ____. 평가자는 `VERIFY.md`와 위 명령으로 확인 가능.

**엣지**
> 자정 넘김은 ____ (날짜+시각을 datetime으로 합쳐 종료<시작이면 +1일)로 처리, `test_____`. 누락은 ____(제외+경고/기본값), 중복은 ____(키 ____ 기준 1건), 상충은 ____(보고하고 계산에서 뺌). 근거: 담당자 답 / DECISIONS 3.

**반례**
> ____ 입력에서 ____ 가 나빠지는 걸 ____(일부러 만든 입력 / 손 검산 / 건수 대조)로 발견. 원인은 ____. ____로 고치고 `test_____` 추가 후 재실행 통과. 더 하고 싶은 검증은 ____.

**AI 협업**
> AI가 ____ 라고 진단·제안했는데 받아들임 — 근거 ____, `____`로 확인. 반대로 ____ 제안은 버림/고침 — ____ 와 안 맞아서(담당자 조건/테스트 실패). 판단은 내가 했고 확인은 테스트·실행 결과로 했다.

## 내 코드 기반 예상 질문 (동적 출제 대비)
실제 서술형은 AI가 내 제출물을 읽고 질문을 만든다. 그래서 wrapup 스킬이 같은 방식으로 예상 질문 8개 + 모범답안을 `QA_CHEAT.md`에 만든다(따로 돌리려면 prompts.md S8-2).
위 고정 유형은 틀, 예상 질문은 내 코드에 맞춘 실전 버전. 둘 다 본다.

## 그 밖에 나올 수 있는 질문
### 문제 정의
1. 이 과제의 핵심 문제를 한 문장으로 정의하면?
2. 담당자에게 무엇을 물어봤고, 그 답이 설계를 어떻게 바꿨나?
3. 처음 과제 설명에 없었는데 나중에 알게 된 조건은?
4. 범위에서 뺀 것과 그 이유는?

### AI 활용
5. AI에게 무엇을 맡겼고, 무엇은 직접 했나? 왜 그렇게 나눴나?
6. AI가 틀린 답을 낸 사례와 어떻게 알아챘나?
7. 프롬프트를 어떻게 구성했나? (목표·맥락·제약·완료조건)
8. 토큰·시간을 아끼기 위해 한 것은?

### 설계·구현
9. 전체 구조를 설명해보라. 왜 그 구조인가?
10. 가장 중요한 규칙(우선순위/예외)을 코드 어디서 어떻게 처리했나?
11. 경계값(동점·정원·빈 값)은 어떻게 결정했나?
12. 외부 자료(공개 레포)를 썼다면 무엇을, 어디까지 썼나?

### 검증
13. 결과가 맞다는 걸 어떻게 확인했나? (테스트·손 검산·교차 확인)
14. 테스트는 몇 개이고 무엇을 검증하나?
15. 통과했지만 아직 불안한 부분은?

### 회고
16. 시간이 더 있으면 무엇을 먼저 할 건가?
17. 알려진 약점 3개는?
18. 다시 한다면 다르게 할 것은?
19. 담당자가 실제로 이걸 쓰려면 추가로 필요한 것은?
20. 이 과정에서 AI 활용에 대해 배운 것은?
