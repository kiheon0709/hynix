# wrapup

## 순서 (10분)
1. `python3 scripts/preflight.py` 와 `python3 -m unittest -v` 재실행. 실패가 있으면 **고칠지 약점으로 남길지** 사용자에게 묻는다.
2. `README.md`에 실행 방법 3줄(설치 없음 / 실행 명령 / 출력 위치)을 적는다.
3. `VERIFY.md` 완료조건 표가 비어 있지 않은지, "미검증" 항목이 솔직하게 적혔는지 확인.
4. `DECISIONS.md` 마지막 섹션(못 한 것 / 약점)에 **최소 3개** 적혔는지 확인.
5. 제출물 목록을 출력한다: 코드 / 출력 파일 / 문서. 임시 파일, 캐시는 제외.
6. DECISIONS.md 2~5번 섹션(구조·엣지케이스·반례·AI 협업)이 비어 있으면 git log·테스트·대화 기억으로 채운다. 지어내지 말고 실제 있었던 것만.
7. 과제가 요구한 문서(예: AI_COLLABORATION.md)가 있으면 내용이 코드·테스트와 맞는지 대조한다.
8. **서술형 치트시트**를 화면에 출력한다(파일로도 `QA_CHEAT.md`). 각 1~3줄, 파일명·함수명·테스트명·명령을 넣는다:
   - Q흐름: 입력 → 모듈A(책임) → 모듈B(책임) → 출력. 상태는 누가 갖나
   - Q검증: 자동검증된 것(테스트명) / 담당자 답에 기댄 가정 / 미구현·미검증 / 평가자가 칠 명령
   - Q엣지: 자정 넘김·누락·중복·상충 각각 처리와 테스트
   - Q반례: 찾은 반례 1개, 찾은 방법, 수정, 재검증
   - Q AI: AI 제안 중 받은 것 1 / 버리거나 고친 것 1, 근거, 확인 방법
9. `docs/qa-prep.md`의 "당일 메모"를 사용자가 채우도록 질문 형태로 띄운다.
10. git add -A && git commit -m "제출" (push는 하지 않는다).
